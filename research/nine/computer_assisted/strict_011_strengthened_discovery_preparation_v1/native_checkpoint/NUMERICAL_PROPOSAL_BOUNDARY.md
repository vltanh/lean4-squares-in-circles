# Exact boundary of the strengthened numerical orchestration

The new source changes proposal orchestration only. The physical and algebraic
premises are the separately frozen full-caller foundation, four-product layer,
strict universal-021 applications, and strengthened complete-tree wrapper.
The unchanged base source is imported by its complete SHA-256 before use.

## Exact residual payment

All printed rows have the form `a_k . z <= b_k`. Numerical dual values only
suggest nonnegative integer weights; each retained weight is divided by
`2^40`. Suppose their exact sum has coefficients `c + r` for a requested
objective `c . z`, with certified absolute variable bounds `|z_j| <= M_j`.
Then

`c . z <= sum_k(lambda_k b_k) + sum_j(M_j |r_j|)`.

The exact verifier recomputes every coefficient and the entire correction,
then rounds the proved upper bound upward to its rational grid. The driver
stores a bound only when the verified value strictly improves the existing
certified endpoint. No numerical tolerance is used as a proof inequality.

For an exclusion, the exact reserve is

`-sum_k(lambda_k b_k) - sum_j(M_j |sum_k(lambda_k a_kj)|)`.

A strictly positive reserve contradicts all the rows simultaneously. The
accepted base `reserve_from_weights`, `bound_round`, and generic independent
arithmetic are used unchanged. SAT auxiliaries, when present, retain their
existing independently reconstructed bounds. The new corner rows themselves
use only the original 54 columns.

## Current boxes and matching LP matrices

The four-product factory first invokes the unchanged fresh model's exact
propagation on the certified state. Its 576 midpoint seed rows and any extra
parameter tuples are expanded on those current intervals. Persisted parameter
tuples come only from already checked printed rows; they are expanded again
after every bound round.

The optional separation function receives a floating-point phase point. It
may suggest rational tangent coordinates and four endpoint choices. Before
adding the row, the independent adapter reconstructs its complete literal at
the proposed printed index, and its independently propagated state and
absolute bounds must equal the factory's state and bounds. Suggestions are
never premises.

After appending any such batch the driver constructs a new backend and solves
that complete row list. At the final allowed pass it returns before appending
anything. Therefore every returned phase dual and each later objective solve
refer to the same final row list. The no-solver changing-point control tests
two successive append passes and checks that this equality still holds.

## Full caller and complete pending alternatives

The copied `Store` class is unchanged. It obtains a certified parent by exact
record replay and constructs every child with the accepted constructors:
four signed coordinate proxies, eight owned separating-axis alternatives, or
both closed halves of a canonical angle interval. It writes all immutable
children before atomically replacing the single manifest pointer. A bounded
run may leave arbitrarily many leaves OPEN; it may not omit one of the
alternatives. The complete checker reconstructs each expected child from its
exact parent and checks equality, not merely interval inclusion.

The numerical `choose_split` function is copied unchanged and has no proof
authority. The small first-use protocol does not split at all. The mixed
no-solver fixture nevertheless exercises all three complete-cover constructors
through the actual new `Store` integration. The ENOSPC control leaves the old
one-node manifest unchanged even when durable, unreferenced child files have
already been written. Those orphan files are preserved as control evidence;
they do not alter the old complete cover.

## Conditional theorem terminals

The producer can propose a guard for C, H, or I only on the current propagated
state and the unchanged complete root document. The independent guard decoder
checks the exact literal before the strengthened adapter starts a fresh
scalar replay. A forged producer PASS is rejected before either the scalar
run or a manifest mutation. The first accepted conditional terminal triggers
the complete accepted scalar proof anew; the independent cold final replay
does so again for its own first true terminal. The scalar output folders are
new and separate from the frozen source packages.

The strict `q < 1105/256` caller uses the seven-original conclusion
`q >= 1105/256` directly. It retains both unused originals and imports neither
actual BC nor an equality blocker. The equality behavior of a closed-radius
caller is not part of this driver's target.

## Evidence and source integrity

The source tree, input manifest, root document, and every input record are
hash-checked before use. Input proof arithmetic is replayed before the output
directory is created. Every proposed output record is checked before its
immutable file and manifest are installed. The final complete checker runs
in a fresh Python process without site imports, then the driver rechecks all
source hashes.

Diagnostic phase points are written atomically in a separate `diagnostics`
directory and marked as numerical only. Neither the complete checker nor the
actual-weight counter treats them as proof records. The counter examines only
new, independently accepted exact rounds and terminals; inherited uses are
excluded. A fake backend used by preparation controls is explicitly excluded
from the actual LP gate even if it supplies a valid hand-written certificate.

The outer source freeze and launch review do not credit a mask. The actual
first-use audit, successful conditional-scalar gate when applicable, and
complete whole-mask cover remain separate obligations.
