# Strict-011 recovery after the second workspace disappearance

This restores existing published sources and one already published exact
conditional certificate. It adds no cell or mask closure and starts no
numerical search.

The source bases are the strict-011 foundations in commit
`58bb59bac06714502b9438e795d61588a5a45671` and the standalone discovery /
first actual LP package in commit
`35ac6d675d74f013a59804ef5506b74b005b59d6`. The parent restored the canonical
repository; the local restoration script only reads it and copies missing
runtime files, rejecting any nonidentical existing target. It does not
modify the Git worktree or index.

The script rehashes both source inventories and compares all 117 first-use
members against the independent surviving `/tmp` packet. It restores 291
files totalling 3,238,372 bytes: 185 foundation files, 94 discovery/control
files and all 12 files from the published five-node pilot. The precise
source/target mapping and each original hash are in the restoration receipt.

The new exact replay uses the published portable checker and the restored
foundation. It checks the complete nine-original strict `011/00` caller,
the whole-caller symmetry identities, the complete four-way AB proxy union,
and the actual four quarter-weight literal sum. That previously proved
conditional reserve is `1/2`; one leaf is excluded and three remain OPEN.
The receipt records the fresh invocation and source identities. No solver
is imported by the exact replay.

The later 33-node bounded frontier, its full-objective continuation and the
running growth frontier were not found in the read-only recovery inventory.
Their historical hashes and messages are not replacements for their proof
records. They are not restored, recredited or used as continuation seeds.
The unpublished H/I guard, C-label attachment and corner-layer preparation
also require explicitly new reconstruction artifacts and fresh controls;
missing old receipts are not replaced by new reports.

The unchanged numerical driver is available for a future root-approved
continuation after a free compute slot is confirmed. None is launched by
this recovery. Small source and exact-proof checkpoints should be committed
before another long numerical run.
