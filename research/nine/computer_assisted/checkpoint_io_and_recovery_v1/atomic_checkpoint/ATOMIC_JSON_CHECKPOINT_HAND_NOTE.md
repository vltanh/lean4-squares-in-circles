# Atomic single-file JSON checkpoints

`atomic_json_checkpoint.write_json(path, value)` retains the established serialization: `json.dump(value, indent=2)` followed by a newline, UTF-8, with the default JSON ordering and escaping behavior. It creates an exclusive temporary sibling, writes all bytes, flushes, preserves an existing regular destination's permission mode (or sets a new file to 0644), fsyncs the file, atomically replaces the destination, and fsyncs its directory. It rejects a symbolic-link or other nonregular destination before staging.

Failure before a successful replacement leaves the prior destination's bytes and inode intact. The partial or complete staging file is retained and the error propagates, with the temporary path and replacement status attached as a diagnostic note. If directory fsync fails after replacement, the new checkpoint has already been installed; this is explicitly reported. The helper attempts to retain a diagnostic hardlink only after checking that the installed inode is exactly the staged inode. Any inability to retain that diagnostic is also reported without concealing the original error.

This is a single-file operation. It is not a transaction between a node and its manifest, and does not claim persistence after an unreported directory-fsync error. The existing exit-time node/manifest hash audit remains necessary. Future immutable drivers must rethrow `OSError` at their outer search boundary instead of handling it as an ordinary failed branch and continuing more checkpoint writes. No current driver was changed or migrated by this preparation.

Eight real-filesystem controls passed in disposable directories. Injected ENOSPC before serialization, during serialization, and at file fsync, plus an injected `os.replace` failure, retained the previous destination bytes/inode/mode and diagnostic stage. Successful writes matched the previous indent2/newline serialization exactly, preserved 0640 mode, and used file then directory fsync. A new file had exact 0644 permissions despite restrictive umask. A post-replacement directory-fsync failure retained the installed data with an exact-inode diagnostic link and reported replacement explicitly. A symlink destination was rejected without changing its target.

No proof arithmetic, source row, accepted count, current numerical worker, or existing checkpoint payload was modified. These are I/O durability controls, not mathematical replay evidence.
