# Independent source review: B exact area-moment runtime

The new runtime preserves the accepted literal family and passes source review
at bounded readiness scope. I read the full wrapper, accepted exact cache
implementation and reference generator, compared the driver text, inspected
the actual B16 parity report, and independently rehashed all396 readiness pins.
No arithmetic replay, optimizer or new numerical search was run for this
review.

The only driver change is its runtime import. Its old branch selector, bound
budget, exact state schema, complete4/8/2 children and atomic checkpoint logic
are byte-identical. The new Context inherits the accepted center runtime and
retains its engine object. It patches only discovery's square-area moment
generator, while the independent row/cover checkers remain unchanged.

The wrapper binds the accepted base, exact reference and exact optimizer. It
requires precisely all36 original pair boxes, immutable Fraction endpoints
with lower<=upper, the fixed subset sizes5..9, stable rational2x2 matrix
sequences, and unchanged lower_bound/name/axes function identities and code.
The generated cache keys include the entire ordered exact difference box,
counts and matrices. Per-pair coefficients are the same sums of exact secant
terms as the reference; each subset retains the same coefficient signs,
constant, names, loop order and zero omission. Cached rows are immutable; the
outer returned list is new. This is literal assembly reuse, not a new
mathematical inequality or altered geometric premise.

The saved actual B16 parity report e24f6217... compares all3072 rows, including
complete coefficients, right-hand sides, names and order. It separately
rejects a missing pair, unstable matrix iterator, different subset sizes and
a mutated lower-bound helper. I inspected and hash-bound that report; I did
not rerun its arithmetic. The reported timings apply only to row assembly,
not to whole-search speed or closure.

The B16 and B462 prepared seed scopes remain explicit. B16 is conditional on
its accepted published prefix; B462 retains its whole-original state. This
source review authorizes no extra numerical lane, does not recover missing
105/107-node suffixes, and grants no original or mask credit. Any future proof
still uses the unchanged exact literal and complete-ancestry checker.
